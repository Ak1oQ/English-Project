# Fashion Check — GitHub + Vercel + Neon

## Что готово

Сайт с общей базой ответов и четырьмя графиками. Настоящая статистика показывается по умолчанию. 70 демонстрационных анкет доступны отдельно, отмечены как демонстрационные и в базу не записываются. Старые локальные анкеты автоматически не импортируются.

Ответы не исчезают при обновлении сайта или повторном развёртывании: они находятся в PostgreSQL. Редактирование и повторная отправка с тем же ключом обновляют существующую запись. Случайный ключ хранится в браузере, в базе — только его SHA-256. Публичный API возвращает только суммарные количества. Счётчик считает анкеты, а не проверенных уникальных людей. Новый браузер, очистка хранилища или кнопка «Следующий участник» позволяют отправить ещё одну анкету. Защиты от ботов и проверки личности нет.

## Как опубликовать

1. Создайте пустой репозиторий на GitHub. Загрузите **содержимое этой папки**, включая папки public, api, lib, db, tests и файлы package.json, package-lock.json, vercel.json, .gitignore. Не загружайте ZIP целиком. Файл package.json должен лежать в корне репозитория.
2. Создайте проект PostgreSQL в Neon: https://console.neon.tech . Откройте SQL Editor, вставьте содержимое db/schema.sql и выполните его один раз. Так создаётся таблица ответов.
3. В Neon откройте Connect и скопируйте PostgreSQL connection string (строку подключения с sslmode=require). Считайте её паролем: **не публикуйте в GitHub, HTML или переписке**.
4. В Vercel выберите Add New → Project и импортируйте репозиторий GitHub. Framework Preset: Other. Root Directory: корень репозитория. Output Directory: public (уже указано в vercel.json). Build Command не нужен; установка зависимостей выполняется автоматически.
5. Перед Deploy добавьте переменную окружения DATABASE_URL со строкой подключения из Neon. Включите её для Production. Если хотите пользоваться Preview, подключите отдельную тестовую базу для Preview, чтобы тестовые отправки не попадали в исследование.
6. Нажмите Deploy. Если добавляете или меняете DATABASE_URL после публикации, сделайте Redeploy. Удалять базу и повторно создавать таблицу при обновлениях сайта не нужно.
7. Откройте адрес сайта с телефона и компьютера. Первая отправка создаёт одну запись. «Изменить ответы» сохраняет изменения без увеличения счётчика. «Следующий участник» создаёт новую запись. На втором устройстве общая статистика появится при открытии, нажатии «Обновить» или автоматически в течение 30 секунд.

В этой поставке не создан и не подключён внешний проект Neon или Vercel. Без DATABASE_URL и таблицы серверное сохранение не заработает: сайт покажет сообщение об ошибке, а не успешную отправку. Если сеть пропала после записи, повторная отправка с тем же ключом не создаст дубликат.

## Где посмотреть все анкеты

Откройте SQL Editor в Neon и выполните:

```sql
SELECT created_at, updated_at, quality, priority, vintage, durability
FROM fashion_responses
ORDER BY created_at DESC;
```

Значения 0–3 соответствуют порядку вариантов в каждом вопросе, сверху вниз. Состав вопросов и порядок вариантов нельзя менять после начала сбора без отдельной миграции. Записи можно выгрузить из базы для анализа. Имя, телефон и email сайт не запрашивает.

## Проверки и разработка

`npm ci` устанавливает зависимости, `npm test` запускает проверки обработки запросов, повторных отправок и статистики. Для локального запуска API используйте Vercel CLI (`vercel dev`) после настройки локальной DATABASE_URL; обычный Python-сервер или открытие HTML двойным щелчком API не запускают. Дизайн статической страницы при этом доступен, но серверные ответы сохранять нельзя. Не храните настоящие пароли в .env.example.

Проверки используют тестовую базу в памяти. Реальное подключение к Neon и публикация Vercel должны быть проверены после настройки внешних сервисов. Пользовательские ответы из прежнего localStorage не отправляются без согласия.
