# Опрос Fashion Check, версия 2

Основной текст сайта остаётся на английском. Опрос и статистика — на русском. Сайт использует Arial и единый серовато-бежевый фон #ede9df.

## Результаты Google Forms

Источник: предоставленные владельцем проекта скриншоты сводки с 27 ответами. Загружены только количества по вариантам. Индивидуальные анкеты не восстановлены и не создавались. Дубликат скриншота вопросов 3–5 не считался второй выборкой.

Порядок количеств соответствует public/survey-config.js:

1. Частота: [0,4,8,5,10]. На исходной диаграмме четыре варианта. «Несколько раз в месяц» добавлен только в новой форме; для исходной выборки этот вариант не предлагался.
2. Приоритеты: [11,6,14,3,9]. Можно несколько ответов: всего 43 отметки у 27 участников. Проценты делятся на число анкет, поэтому сумма превышает 100%.
3. Цена и качество: [7,11,4,5].
4. Снижение качества: [6,8,5,8].
5. Быстрый износ: [1,11,13,2]. Малый сектор — остаток от 27 при известных трёх других количествах.
6. Переплата за бренд, оригинальные пять вариантов: [3,9,7,2,6]. В частности, 9 ответов «Да, если мне нравится вид вещи» нельзя приписать другому варианту в новой форме. Поэтому исходный график показывается отдельно от новой версии на четыре варианта. Последняя считает только ответы с сайта.
7. Винтажный опыт: [3,8,4,12].
8. Причины покупать винтаж: [6,3,6,0,12].
9. Проверка качества: [16,3,6,2].
10. Чек-лист: [10,10,7].

Общий счётчик: 27 исходных анкет + число новых анкет на сайте. Подсчёт количества анкет не подтверждает уникальность людей. Одни и те же люди могут повторно пройти анонимный опрос.

## Хранение новых ответов

API использует DATABASE_URL, которая уже настроена в Vercel. При первом обращении автоматически создаётся отдельная таблица fashion_responses_v2. Старую таблицу fashion_responses и прежние анкеты из четырёх вопросов API не изменяет и не добавляет к новой статистике: это другой опрос. Для автоматического создания у роли базы должно быть право CREATE в текущей схеме; при отсутствии права владелец может выполнить db/schema.sql в Neon вручную.

Ключ браузера сменился на fashion-check-cloud-v2. Случайный 256-битный ключ позволяет редактировать свою новую анкету; сервер хранит его хеш. Повторная отправка с тем же ключом обновляет запись. Прежние локальные данные автоматически не отправляются. Общедоступный GET /api/votes возвращает только сводные количества. Данные Google Forms не записываются повторно в таблицу при обновлениях сайта.

Новый контракт POST: {version:2,token:"64 hex characters",answers:{frequency:0,priorities:[0,2],priceQuality:0,qualityDecline:0,wear:0,brand:0,vintage:0,vintageReasons:0,inspection:0,checklist:0}}. Индексы соответствуют порядку вариантов в survey-config.js. Для всех вопросов кроме priorities нужен один индекс; для priorities — непустой массив уникальных индексов.

Запуск проверок: npm test. Тесты используют базу в памяти. Проверка действующего подключения к Neon требует развёртывания. Для просмотра сайта нужен HTTP-сервер, поскольку script.js — модуль: python -m http.server 8000 --directory public. Локальный Python-сервер не выполняет API: в таком просмотре отображаются только исходные 27 анкет с сообщением о недоступности сервера.
